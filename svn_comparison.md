Git vs SVN: ответы на вопросы

1. **Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?**
   В Git ветка — это всего лишь ссылка (40-символьный хэш), указывающая на определённый коммит. Чтобы создать новую ветку, достаточно добавить ещё один указатель — это занимает миллисекунды и не требует копирования файлов. В SVN же ветка реализована как реальное копирование директории на сервере (команда svn copy trunk branches/x), а значит, требуются время, дисковое пространство и обращение к центральному серверу по сети.
2. **Можно ли в SVN сделать коммит без интернета? Почему?**
   Нет, нельзя. SVN — централизованная система: вся история хранится только на сервере, а у разработчика локально есть лишь рабочая копия текущей версии файлов. Любой коммит представляет собой сетевую операцию записи в центральный репозиторий, поэтому без связи с сервером он невозможен — можно лишь редактировать файлы у себя.

3. **В каких сценариях SVN до сих пор может быть предпочтительнее Git?**
   - Устаревшие системы в госструктурах и банках, где переход на Git слишком дорог и сопряжён с рисками.
   - Проекты с большим объёмом бинарных файлов и жёсткой централизованной моделью доступа и аудита, где важно, чтобы все действия проходили через единственный подконтрольный сервер, а не расходились по локальным копиям.
   - Команды, которым нужен детальный контроль доступа на уровне отдельных поддиректорий — в SVN это реализовано проще и естественнее, чем в Git.
